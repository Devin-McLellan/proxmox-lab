### Network Layout (Discovered)

| Bridge | Interface | Purpose |
|--------|-----------|---------|
| `vmbr0` | `nic0` | Main bridge, trunk port |
| `vmbr20` | `nic0.20` | Lab VLAN 20 |
| `vmbr99` | `nic0.99` | Cluster heartbeat VLAN 99 |

**Note:** Using `vmbr0` with VLAN tag 20 caused a conflict (`nic0.20 already exists in bridge vmbr20`). Use `vmbr20` directly for lab VMs.

---

### Problem Identified: No Gateway on VLAN 20

During Debian installation, network autoconfiguration failed:
> "Your network probably is not using the DHCP protocol"

**Root cause:**
- VLAN 20 has no DHCP server and no default gateway configured
- TP-Link TL-SG105E switch handles VLAN switching but cannot route between VLANs
- Consumer router (Inseego) does not support VLAN-aware routing

**Workaround:** Skipped network configuration during install. Will configure after OPNsense is set up.

---

### Solution: OPNsense VM as Router/Firewall

Deploy OPNsense as a VM on Proxmox to handle:
- VLAN gateways (e.g. `192.168.20.1` for VLAN 20)
- DHCP per VLAN (replaces planned DHCP01/DHCP02 VMs)
- Firewall rules between VLANs
- Internet routing from VMs through physical router

**After OPNsense:** Set default gateway on all VMs to OPNsense's VLAN interface IP.
